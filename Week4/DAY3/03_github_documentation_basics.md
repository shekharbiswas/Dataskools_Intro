# 📘 GitHub Documentation Basics

Today you’ll organize your work from Week 3 and 4 in a clean GitHub repository.  
This will help you build good habits and create something you can share in your portfolio.

<br>

## 📁 Organize Your Project Folder

Create a folder or GitHub repo like this:

<pre>

Lemonade-project/
├── cleaned_data/ ← for your cleaned spreadsheet files
├── charts/ ← for charts or images you created
├── analysis_notes/ ← for your written notes and insights
├── README.md ← explains what your project is about
└── journal/ ← for your personal reflection
</pre>

### 💡 Tips

Keep file names simple and clear.  
✅ Good: `cups_sold_by_day.png`  
❌ Avoid: `chart1.png` or `final_final_updated2.csv`

## 📝 Write a README.md

Your `README.md` is the front page of your project. It tells people what your project is and what you learned.

Include these things:
- **Title:** What is this project called?
- **Goal:** What were you trying to do?
- **Tools:** What tools did you use (Google Sheets, etc.)?
- **Insights:** What did you find in the data?
- **What You Learned:** What did this project teach you?

Example:
> Lina’s Lemonade Sales – I explored which flavors sold best and how sales changed by day. I used Google Sheets to clean and visualize the data. I learned how to spot outliers and trends using charts.

<br>

## 🧾 Write Your First Data Journal Entry

Make a new file called:  
`journal/week-3-reflection.md`

Write a few sentences to answer:
- What surprised you?
- What was difficult?
- What are you proud of?

Example:
> I was surprised to see mint flavor sold the least.  
> It was hard to clean the “Flavor” column because the names were inconsistent.  
> I’m proud that I created my first pie chart and explained it clearly.

<br>

## 💡 Why This Matters

Good documentation helps others understand your work — and shows that you’re serious about learning.  
When you apply for jobs later, your GitHub page can help you stand out.  
Even one well-organized project shows your thinking, effort, and growth.
